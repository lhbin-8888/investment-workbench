## 一、你确认的三条平台口径 → 对设计的直接影响

| 口径 | 直接影响 | V3 的处置 |
|------|---------|----------|
| `get_history` **含当日 bar** | V2 声称的 R2「只用已收盘数据」在 14:45 物理上不成立——当时的 `closes[-1]` 是**进行中的当日 bar**。V2 既没承认也没处理，等于把 V1 被否决的 S-2（口径不确定）原样保留 | **拆开两个口径**：选股用「T 日 14:55 尾盘快照」并**如实标注**为尾盘近似；价格锚改用 **T 日真实收盘价**（于 T+1 读取，此时已收盘、完全精确）。全链路无未来函数 |
| volume 单位是**股** | V2 的 `amount = vol × 100 × close`（line 293）把 3 亿门槛**悄悄降到 300 万**，选股过滤形同不存在 | 改为 `amount = vol × close`，**不乘 100**；并在信号层打印一次量纲标定行（`[量纲标定]`）供复核 |
| `order_value` 限价参数名是 `limit_price` | V2 写的是驼峰式 `LimitPrice=`（line 643），参数不符会抛 `TypeError`，而异常被 `handle_data` 的 try/except **吞掉** → 表现为「策略正常跑、就是不下单」，正是 V1 被否决的 P0-2（谎报正常） | 改为 `order_value(..., limit_price=upper)`；并新增 `on_order` 回执，下单返回空一律进降级告警 |

## 二、V3 的时间线与口径（核心设计）

```
T 日 14:55  signal_job   选股：读含当日 bar 的日K → 板块强度/三阶段/候选
                         （口径：尾盘快照，如实标注，不再自称"已收盘"）
        ↓ 候选只存代码与特征，不存价格
T+1 09:31   open_job     ① 补卖昨日可卖=0 的队列
                         ② 取 closes[-2] = T 日真实收盘价  ← 限价锚（精确）
                            取 open[-1]   = T+1 开盘价
                         ③ 双边限价校验 → order_value(..., limit_price=锚×1.03)
T+1 盘中    handle_data  每分钟风控（零额外取数：日K在日初已缓存）
T+1 14:58   risk_fallback_job  盘内兜底风控（V2 原为 15:10，已在交易时段外）
```

**为什么锚要放到 T+1 取**：T+1 09:31 时 T+1 当日 bar 已生成，`closes[-2]` 就是 T 日的**最终收盘价**——已收盘、无未来函数、且是成交前一刻取到的最新已收盘价。这同时解决了 V2 的两个问题：口径不确定，以及限价锚取成 T-1 收盘。

**V2 的限价错位有多严重**（本次验证实测值）：

```
候选 600013：T 日收盘 = 16.47，T-1 收盘 ≈ 15.39
  V2 限价 = 15.39 × 1.03 = 15.85  ← 低于 T 日收盘 16.47
  V3 限价 = 16.47 × 1.03 = 16.96  ✓
```

V2 的限价**低于候选当日收盘价**，意味着 T+1 只有**低开**才会成交 → 系统性地只在下跌时买入，与 V1 被否决的 S-1（逆向选择）同病。

### 3.2 交易逻辑

| # | V2 问题 | V3 处置 |
|---|--------|--------|
| L-1 | 限价锚取 T-1 收盘，低于 T 日收盘 → 只在低开成交 | 锚改 **T 日真实收盘**；**双边限价** `[×0.985, ×1.03]`，开盘价越界一律放弃（低开不接刀、高开不追） |
| L-2 | `stage`（三阶段）与 `ladder`（梯队）**全篇只有 log.info，没有任何代码消费** | `stage` 接入两处决策：**候选生成**（衰退期一票否决；扩散期只做"温和涨幅+缩量"回踩；启动期正常）与**板块级清仓** |
| L-3 | `strength = zt×5 + up×1 + …` 首项正比于成分数 N（15~400，26 倍跨度）→ 主线长期是「融资融券/参股金融/专精特新」 | 强度改为**比例口径**：`zt_rate×50 + up_rate×10 + ratio_up×20 + avg_pct`；另加宽口径黑名单 + `MAX_SECTOR_SIZE=80` + Jaccard 去重 |
| L-5 | 文档承诺"板块联动清仓"，代码里**完全没有** | `_sector_killed()`：stage=衰退 **或** 板块涨停家数自峰值腰斩 → 清该板块全部持仓（早于单票止损） |
| L-6 | `MIN_HOLD_DAYS=17` 是**从未被引用的死常量**；-3% 止损与"平均持仓17日"数学互斥；无任何换手约束 | `turnover_ok()` 滚动 365 天双边换手统计，超 21 次**停开新仓**；止损改 **ATR(14)×1.8**（夹在 4%~8%），并设 `MIN_HOLD_FOR_TIGHT_STOP=5` 日抑制噪声止损；`STOP_MODE="fixed"` 可一键切回固定 -3% |
| L-7 | "缩量停单"实现成了"现金不足停单"（账户级），无**市场级**开关 | `market_regime_ok()`：池内涨停家数 < 25 或指数破 MA20 → 停开新仓；数据全部来自已有缓存，零额外请求 |
| L-8 | 量比 = **半日量** ÷ 完整5日均量，系统性低估约半 | 按当日已交易分钟折算（`240/elapsed`） |
| L-9 | 无相对流动性约束 | `MAX_AMT_SHARE=0.005`：单票买入额 ≤ 当日成交额×0.5% |
| L-10 | 无移动止盈；`int(amount*0.5)` 未取整到 100 股 | 新增 `TRAIL_PCT=8%` 移动止盈；`_round_lot()` 取整到 100 股（不足一手全卖） |
| — | `RETREAT_MA=20` 与决策3「破5日线清仓余仓」不符 | `RETREAT_MA=5`，对齐决策 3 |

## 四、离线验证结果

验证器不联网、不上平台：用真实结构的板块池（含 400 只级宽口径标签、60 只级题材、250 只级超限板块）+ 合成日K，
注入 mock 版 PTrade API，把 `initialize → before_trading_start → signal_job → open_job → handle_data/风控` 全链路跑通。

| 模式 | 模拟的平台行为 | 断言 | 失败 |
|------|--------------|------|------|
| `dict` | `get_history(..., is_dict=True)` → `{code: DataFrame}` | 80 | 0 |
| `multiindex` | 返回 MultiIndex 列的单个 DataFrame | 80 | 0 |
| `single` | 不支持多证券 → 逐票（扫描范围自动收缩） | 82 | 0 |
| `nofq` | `get_history` 不接受 `fq` 参数 | 82 | 0 |
| **合计** | | **324** | **0** |

复跑：`python verify_v3_mock.py [dict|multiindex|single|nofq]`，也支持 `--mode dict` 写法（退出码 0 = 全通过）。
模式名写错时脚本**直接报错退出**，不会静默退回默认模式——否则会出现"跑的不是你以为的那个模式却全绿"的假通过。

覆盖的关键行为：标识符统一 / 五档涨跌幅 / 批量取数量纲 / 封板剔除 / 持仓排除 / 冷静期 / ST 剔除 / 限价锚=T日收盘 / 低开不接刀 / 高开不追 / 切片不错位 / 三阶段接入 / 板块级清仓 / ATR止损+最短持有期 / 可卖=0入队 / 换手熔断 / 市场开关 / 四条降级路径。

**注意**：验证的是**逻辑正确性**，不是真实行情下的收益表现。回测（对应原方案 M3）尚未做。

## 六、上线前必须自己核对的平台接口

代码已对下列每一点做了容错或降级，但**降级不等于正确**——降级会打日志，请确认日志里没有：

| 接口 | 代码行为 | 要确认 |
|------|---------|-------|
| `get_history(..., is_dict=True)` | 探测 `dict / multiindex / single` 三形态 | 形态是哪一个；是否为 single（会收缩扫描范围） |
| `get_history(..., fq="pre")` | 不支持则告警后改不复权 | 是否出现 fq 降级告警（复权口径变了，信号会跟着变） |
| `run_daily(context, func, time=)` | 不支持则退回 `handle_data` 容错窗口 | 是否出现 `run_daily 不可用` 告警 |
| `get_positions()` 字段 | `security / current_amount / enable_amount / cost_price / last_price` 多路径尝试 | 实盘首日持仓字段是否被正确读到（看风控日志有没有"无法取值"） |
| `set_commission(...)` | 依次尝试 `commission_ratio+tax` → `commission_ratio` → `PerTrade` | 印花税是否被接受（拒绝会降级，成本口径变乐观） |
| `on_order` 回调 | 字段 `security/status/amount/filled/error_info` | 回执是否打印正常；字段名不符只影响日志，不影响交易 |
