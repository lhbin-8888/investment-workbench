## 一、启动方式

> ⚠️ **必须通过本地 HTTP 服务打开，不能直接双击 `index.html`。**
> 晨报模块使用 `fetch('data/YYYY-MM-DD-晨报.pdf')` 动态加载，浏览器在 `file://` 协议下会因 CORS 策略拦截，导致晨报一片空白。

**方式二：命令行**
```bash
cd /d/投研工作台
python -m http.server 8848
# 浏览器访问 http://localhost:8848/index.html
```

## 六、网页端与小程序端同步机制

**核心原则：`index.html` 是唯一数据源（single source of truth）。**

小程序端所有模块结构、描述文案、模板内容、晨报快照，全部由 `index.html` 自动生成，**不要手工编辑 `miniprogram/app.js`**。

### 同步脚本

```bash
# 1. 同步数据（改完 index.html 后必跑）
node tools/sync-miniprogram.js

# 2. 校验两端结构是否一致
node tools/check-alignment.js
```

`sync-miniprogram.js` 从 `index.html` 提取 `NAV`（导航分组）、`README`（子模块说明）、`TM`（模板正文）三个数据块，并从 `data/` 读取最新晨报，生成 `miniprogram/app.js`。网页端 slogan 也一并提取，保证两端文案一致。

`check-alignment.js` 校验：两端子模块数量是否一致、小程序页面引用的子模块名是否都存在、晨报快照是否存在。全部通过才输出「两端结构完全一致」。

### 两端对应关系

| 网页端导航分组 | 小程序 tabBar | 小程序页面 | 子模块数 |
| --- | --- | --- | --- |
| 投研分析 | 投研分析 | `pages/market/market` | 3（含每日晨报） |
| 交易管理 | 交易管理 | `pages/review/review` | 4 |
| 投研研究 | 投研研究 | `pages/research/research` | 16（含工具与模板 3 项） |

首页另保留 7 大模块入口，可直达 `analysis` / `strategy` / `templates` 页面（这三个页面不在 tabBar 中）。

### 小程序端的固有限制

微信小程序是纯前端沙箱，**无法读取本地文件系统**，因此：

- ❌ 不能像网页端那样 `fetch('data/*.pdf')` 加载晨报 PDF
- ✅ 替代方案：`sync-miniprogram.js` 把最新晨报的 **Markdown 文本**内嵌进 `app.js`，小程序展示文本快照
- ⚠️ 快照是**生成时刻的静态副本**，每次出新晨报后需重跑一次同步脚本才会更新

详情页会明确标注「本页为晨报文本快照，PDF 完整版请在网页端查看」，避免误认为实时数据。
