## 五、本轮新暴露的缺陷（D16 ~ D21）

### D16【P0】L1 底仓被 L2 规则反复清空 —— 仓位单向衰减的真正原因

- **代码事实**：`_daily_risk_scan()` 的 docstring 写着"L1 核心仓长持，不在此处理"，但实现只判断 `if code not in L2_SET: continue`——**持仓没有任何层级归属标记**。而 `L2_SET`（10 只）**全部包含在 16 只 L1 池内**。
- **后果**：12 笔 L2 退出卖出的是 `L1建仓` 的股票。01-05 建立的 9 只 L1 底仓中，601899、002027、600938、600900 被逐个清空。
- **量化证据**：
  - 持仓占比 53.5%（01-05）→ 46.1% → 39.8% → 35.4% → 22.2%（03-20）→ 18.2%（07-17）
  - 平均持仓占比仅 **37.0%**，与名义 83% 差 46 个百分点
  - **最刺眼的一处**：07-07 季度再平衡重建 4 只，**次日 07-08 就被 L2 以"移动止盈回撤 8%"卖掉 3 只**
- **修复方向**：建仓时写入 `owner_layer[cd] = "L1"/"L2"/"L3"`，`_daily_risk_scan` 与 `_intraday_hard_stop` 跳过 L1 归属持仓（或在 L2 卖出 L1 标的时由 L1 层在下个再平衡窗口自动回补）。

### D17【P0】换手预算"累加制"导致 L2 永久锁死

- `_turnover_ok()` 用 `ytd_turns * 250 / days` 做年化，而 `ytd_turns` **只增不减、不滚动**。
- 01-30（第 20 个交易日，样本刚够 `TURNOVER_MIN_DAYS`）年化一度冲到 **187.5 回合**，此后 **74/160 个交易日（46%）** 持续挂"暂停新开 L2/L3"，直到最后一天仍是 46.4，从未回到 7.5 以内。
- **直接后果：`[L2-买]` 全期 0 笔。** 名义上的"三层"实际只剩 L1 + 单边卖出的 L2。
- 口径也有问题：`COST_PER_TURN = 0.20%` 对应"买＋卖"完整回合，而 L3 的卖出（`_record_turn("T")`）与回补（`_record_turn("T", True)`）被拆记两次 `round_trip`，把年度预算凭空放大一倍。
- **修复方向**：改为滚动 250 交易日窗口；T 记账改为"1 个完整 T（卖＋回补）= 1 回合"。

### D18【P0】L3 日内 T 绕过统一委托出口

- 第 **1280 / 1297 / 1323** 行仍直接调用 `order_target_value`，违反 V1.1 自定的"唯一出口"约定（第 647 行注释）。
- 后果三连：
  1. 24 笔 T 委托**完全未进 `[交易执行]` 统计**（`已提交 54` 与平台实际 41 笔的差额来源之一）
  2. 拒单不会触发 `_note_reject` → 熔断机制在 T 路径上失效
  3. `_record_turn` 在 `order_target_value` 之后无条件执行 → **D11 幽灵状态在 T 路径上依旧存在**
- **修复方向**：T 的开仓/回补/强平三处改走 `_submit_order`（或复用 `_do_sell` / `_do_buy_value`）。

### D19【P1】统计口径标签误导

- `[统计] 委托口径：已提交54 被平台拒0 有效54` —— 这里的"已提交"实为 `STATS["n"]`，即 `_record_turn` 的**记账次数**，不是平台委托笔数。
- 实际：平台委托 **41 笔**（18 L1建仓 ＋ 12 L2退出 ＋ 11 L1减仓），差额 13 笔来自 L3 的双边记账。
- **修复方向**：拆成四行——平台委托数 / 受理 / 被拒 / 记账笔数，并给"记账口径"明确命名。

### D20【P2】首日 74 条 `回测不支持get_snapshot函数` 告警

- **全部集中在 2026-01-05 08:30**（时间分布统计：74 条、唯一时刻 1 个）。
- 原因：盘前 `g["cur_data"]` 尚未赋值（只在 `handle_data` 里设置），`_ref_price` → `_cur_price(code, None)` → 退到 `get_snapshot` → 回测环境不支持。
- 已有 `_hist_lists(5,"1d")` 历史收盘兜底，**功能无损，纯噪音**。
- **修复方向**：`_cur_price` 中 `data` 为 None 时直接返回 `(None, "none")`，不尝试 snapshot。

### D21【P2】同日同标的矛盾委托

- 07-14 对 `600900.SS` 在同一 tick 下了两笔：先「市场开关 L1 减仓」目标 25,578 元，再「L2 超买 RSI71」目标 0 元。两笔**均被受理**。
- 结果无害（最终清仓），但说明 `_has_open_order`（查在途委托）只能防"多标的重复"，防不住"同日同标的语义冲突（先减后清）"。
- **修复方向**：`_flush_pending` 出队时按标的做冲突合并——同一标的保留"最后一个目标值"。

## 六、收益结构解读：为什么只有 +3.49%

拆成三个可量化的因子：

**① 仓位不足（主因，贡献最大）**
名义目标 83%，实际平均仅 37%。现金长期占 60% 上下，最高达 81.8%（07-17）。那一小部分仓位即便有正收益，也很难拉动整体净值。上表已示：这不是本金问题（30 万下无硬顶），而是 D16 造成的持续失血。

**② 成本拖累与收益同量级**
24 个完成回合 × 0.20% ≈ 48 个百分点的成本口径；折年化约 **7.5%**，而年化收益 5.46%。**换手成本几乎吞掉了全部超额收益。**

**③ 市场环境偏弱**
160 个交易日中有 **68 天**报"沪深300 在 60 日线下方"、6 天报"在 120 日线下方"。市场处于中长期均线下方，属于防守型环境。在此背景下 +3.49%／回撤 -4.71% 属于抗跌，但谈不上进攻。（本回测日志未记录沪深300 点位，无法给出精确基准对比，建议后续在策略里补一行指数净值日志。）
