## 二、改造规格一：大市闸门（决策1）

### 2.1 现状（据日志反推）
- `HALT`（指数破位）：**禁止新建仓 + 对触发退出条件的持仓执行退出**（清零倾向）。
- `PAUSE`（振荡/不确定）：**建仓额度 × 0.5**。
- 复位（指数重新站上）：**无主动回补**。
- 实测影响：HALT 67 天 + PAUSE 19 天 = **86 天（53.8%）** 禁止/减半建仓；被拦 62 次，当天候选中位仍有 78 只（从不缺票）；7 月连续 21 个交易日 HALT。

### 2.2 改造目标
| 状态 | 原行为 | 新行为 |
|---|---|---|
| HALT | 清零式禁建+退出 | **设仓位上限**（不清零），持仓仍按原止盈止损管理 |
| HALT 期 | — | 进入时若当前仓位 > 上限，**同步降档**（保留长线核心底仓，仅降热点卫星仓） |
| PAUSE | 额度×0.5 | 同上，设更高一档仓位上限 |
| 复位 | 无动作 | **分批回补**：在 N 日内分步回到目标仓位 |

### 2.3 关键参数（建议值，待源码确认可调）
```
HALT_MAX_WEIGHT   = 0.30   # HALT 期持仓上限（绝对仓位）
PAUSE_MAX_WEIGHT  = 0.60   # PAUSE 期持仓上限
RESET_RECOVER_DAYS= 5      # 复位后分批回补窗口（交易日）
RESET_RECOVER_STEP= 0.20   # 每步回补目标缺口的比例（5步补满）
CORE_PROTECT      = True   # 降档时保护长线核心底仓不降
```

### 2.4 伪代码
```python
def market_gate_v2(state, cur_weight, target_weight, layer):
    cap = {"HALT": HALT_MAX_WEIGHT, "PAUSE": PAUSE_MAX_WEIGHT}.get(state, 1.0)
    if state in ("HALT", "PAUSE"):
        if cur_weight > cap:
            # 降档：优先降热点卫星仓，长线核心底仓受 CORE_PROTECT 保护
            reduce_to(cur_weight, cap, protect_core=CORE_PROTECT)
        # 仍按原止盈止损规则管理现有持仓，不再清零
    else:  # NORMAL / 刚复位
        if just_reset_from(("HALT", "PAUSE")):
            start_batch_refill(target_weight, RESET_RECOVER_DAYS, RESET_RECOVER_STEP)
```

## 三、改造规格二：单票上限降到 20%（决策2）

### 3.1 现状（据日志反推）
- 72 笔买入中 **30 笔超过净值 25%**，最大单票 **33.3%**。
- 6/26 单日 −3.70%（最差日）即由单票过度集中引发。

### 3.2 改造目标
- 单票持仓上限由 **25% → 20%**。
- 并行标的数建议 **5~6 只**，分散集中度风险。

### 3.3 伪代码
```python
SINGLE_MAX_WEIGHT = 0.20   # 原 0.25
def plan_position(code, planned_value, net_value, held_value):
    cap = net_value * SINGLE_MAX_WEIGHT
    return min(planned_value, cap - held_value)  # 不超过单票上限
```

## 四、改造规格三：688 开头票折半（决策3）

### 4.1 现状（据日志反推）
- 688（科创板）硬止损 **20 笔均 −7.64%**，最差 **−12.3%**，**已穿透 ATR clamp 上限 11%**（跳空/跌停开盘）。
- 残仓 bug 也发生在 688112（5/21 委托 1200 股仅成交 500，剩 700 股脱管，7 月 −38%）。

### 4.2 改造目标
- 688 开头标的建仓金额/股数 **× 0.5**（折半敞口）。
- 配合：688 硬止损 clamp 上限由 11% **收紧至 9%**（降低跳空穿透幅度）。

### 4.3 伪代码
```python
def plan_order(code, value):
    if code.startswith("688"):
        value *= 0.5          # 折半敞口
        hard_stop_clamp = 0.09 # 收紧硬止损上限
    return value
```

## 五、改造后预期影响（务必配套评估）

| 指标 | 方向 | 依据 |
|---|---|---|
| 平均仓位 | ↑ 27.9% → 目标 40~60% | 闸门改上限+复位回补，消除 53.8% 禁建时段 |
| 策略收益 | ↑ 每 +1% 仓位 ≈ +1.06pp（拟合 R²=0.71） | 月度收益 ≈ 0.40×仓位 − 7.75 |
| **最大回撤** | ⚠️ **等比放大** | 满仓等效回撤 ≈ 10.42% ÷ 27.9% ≈ **37%**，提仓位会放大回撤 |
| 单票风险 | ↓ 单日最差 −3.70% 类事件减少 | 单票上限 20% + 688 折半 |
| 残仓失控 | ↓ 需补"台账↔平台"对账 | 见诊断报告第 1 优先级（真 bug） |

> **关键提醒**：决策1（提仓位）会把回撤等比放大。决策2（单票20%）+ 决策3（688折半）正是回撤放大的**前置对冲**，三者必须一起上线，不可只改闸门。
