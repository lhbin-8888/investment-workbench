## 4. ★关键发现★ "赢家锁利"是死代码

### 4.1 铁证：41/41 样本"最高 == 当前"

日志中 41 条 `进入赢家宽管` 全部形如：

```
[风控] 300319 进入赢家宽管（当前浮盈130.0%，最高130.0%，回撤门限24.0%...）
[风控] 300319 进入赢家宽管（当前浮盈119.5%，最高119.5%，回撤门限24.0%...）
```

**"最高浮盈"永远等于"当前浮盈"**（正则核验：`当前浮盈([\d.]+)%，最高\1%` 命中 **41/41**）——峰值从未被记录。

### 4.2 根因（V4.10 第 2461 行附近）

```python
# V4.10（有 bug）
_pk_prev = g.winner_peak_pnl.get(code, _pr_now)   # ← 缺省值取成了"当前浮盈"
if _pr_now > _pk_prev:                             # ← 首次 _pr_now > _pr_now 恒 False
    g.winner_peak_pnl[code] = _pr_now              # ← 键永不落库
```

→ `g.winner_peak_pnl` 键**永不写入** → ③b 分支 `_pk = g.winner_peak_pnl.get(code, 0.0)` 恒为 **0.0** → `_pk > 0` 恒 False → **锁利分支成为死代码**（41 次进入、0 次锁利）。

### 4.3 差分证明

用同一段 Test 6 逻辑跑 **V4.10**：首次后 `winner_peak_pnl['WIN.SZ'] = None`、锁利触发 0 次
（可复跑脚本 `热点早盘001_V4.11_差分证明.py`，退出码 0 即证明成立）→ 证明 Test 6 是有效回归护栏。

## 6. ★待验证 / 潜在风险★ 修复后的 8pp 锁利可能"过紧"

`WINNER_GIVEBACK_PCT = 8pp` 是**浮盈百分点**尺。对超大赢仓，它远紧于 ③ 的 24% 价格回撤尺：

- 例：浮盈 +74% 时，24% 价格回撤 ≈ 浮盈回落 **42pp** 才触发 ③；而 ③b 只要回落 **8pp** 就清仓 → **③b 实际接管并否决了宽管**。

**对本次 300319 的推演**（用日志 09:31 浮盈序列，峰值滚动）：

| 日期 | 浮盈 | 滚动峰值 | 峰值−当前 | 8pp锁利 |
|---|---|---|---|---|
| 06-08 | +74.2% | 74.2 | 0 | — |
| **06-09** | **+64.1%** | **74.2** | **10.1pp** | **→ 触发清仓** |
| … | … | … | … | （V4.10 实际持有至期末 +110.6%） |

→ 若 V4.11 的锁利按此生效，**300319 会在 06-09 附近以 ~+64% 被清掉**，而非持有到期末 +110.6%，**单此一只可能少赚约 −2.6pp**。
（仅按每日 09:31 快照推演，实际盘中每分钟判定，可能更早触发。）

**结论**：修复让功能生效，但"8pp 固定尺"对高波动大赢仓可能过紧，**需重跑 V4.11 实测**其净效果——是"锁住利润"还是"砍掉主线尾巴"。若过紧，候选调整：把 ③b 门槛改为**随浮盈放大的相对尺**（如 `max(8pp, 峰值浮盈×40%)`），或仅对"浮盈 < 某上限"的赢仓启用锁利、大赢仓仍交 24% 价格宽管。
