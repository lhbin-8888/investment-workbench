## 零、这版为什么换方向

V4.5 → V4.8 四版的火力**全在出场端**（时点闸门、限价、降频、两段式），收益曲线却是
`−0.2% → −2.6% → −2.1% → −1.9%`，在噪声区间里原地打转。

本轮先做了一次**归因**（不看策略的买卖信号，直接用真实行情重算 26 笔买入），得到三条结论：

| 结论 | 数据 |
|---|---|
| **选股不是瓶颈** | 同期中证1000 跌 3.85%、上涨概率仅 11.5%；策略选的票持有 5 日 −0.53%、胜率 42.3% ⇒ **超额 +3.32 pp** |
| **利润极度集中** | **前 3 笔 +87.3 pp，其余 23 笔合计 −19.7 pp** |
| **赢家都是"没人管"的** | 前两名 301366（持 25 天 **+40.6%**）、300747（持 18 天 **+29.3%**）都没触发任何规则；而平均持仓仅 **6.50 天** |

⇒ **"赚钱的全是被忘了管的，被规则认真照顾的反而在亏"**，这就是 V4.9 的设计依据。

## 一、改动清单

### P0-1 ⚠️ 修正：不降低入场限价（**推翻上一版归因的建议**）

上一版归因说"入场价口径值 +1.75 pp、零风险白送"，**这个处方是错的**。V4.9 在落地前用真实 OHLC
重新校准了限价，结果推翻了它：

| 限价 K（× c_prev） | 成交率 | 成交均价 / c_prev | 相对现状改进 |
|---|---|---|---|
| **1.030（V4.8 现状）** | 100% | 0.9919 | — |
| 1.015 | 96% | 0.9902 | +0.17 pp |
| 1.010 | 96% | 0.9896 | +0.23 pp |
| 1.005 | 92% | 0.9884 | **+0.36 pp** |
| 0.980 | 73% | 0.9780 | +1.39 pp |

**错在哪**：归因比的是两种**记账口径**的收益差，但策略实际走 `order_value(..., limit_price=)`，
**成交价由引擎撮合决定，与 assumed 假设价无关**。

**而 V4.8 已经在享受低开成交**：77% 的票 T 日低开 → 限价虽是 `c_prev×1.03`，
实际成交均价已 ≈ `c_prev×0.9919`（≈ 开盘价）。

**更要命的是会筛掉最大赢家**：301366（开盘 +1.7%）与 300747（开盘 +1.8%）
正是 +40.6% / +29.3% 的两笔最大利润来源，限价设 `c_prev×1.00` 就买不到它们。

⇒ **三项参数一律维持 V4.8 原值**：`ASSUME_ENTRY_PREMIUM=0.01`、
`BUY_LIMIT_SLIP=0.02`、`BUY_PREMIUM_PCT=0.03`。

> 归因报告第四节已加醒目更正块。教训已写入 PTrade 技能库。

### P0-2 主线分散（新增，替代"拉黑稀缺资源"）

归因发现「稀缺资源」一条主线独占 **8/26 笔（占样本 31%，也是最大一块仓位）**，
均值仅 **+0.3%**、中位 −3.3%、胜率 **38%**；而元件 +11.0%、玻璃基板 +12.8%。
⇒ 拖累来自"过度押注同一条主线"，**不是**"板块内部选错了个股"。

但**按板块名拉黑只会过拟合这一个回测区间**（换个时期主线完全不同），
故改为通用的**次数约束**：

| 参数 | 值 | 说明 |
|---|---|---|
| `MAINLINE_MAX_ENTRIES` | **4** | 同一主线滚动窗口内最多建仓笔数（≤0 关闭） |
| `MAINLINE_WINDOW_DAYS` | **20** | 滚动窗口（交易日；内部按 ×7/5 折算自然日） |

新增 `g.mainline_entries` 流水 + 辅助函数 `_mainline_recent_entries(sec)`。

### P0-3 赢家宽管（本版核心：让利润奔跑）

浮盈达到 **15%** 的持仓进入"赢家状态"，**放宽**（不是豁免）两条卖出判据：

| 参数 | 值 | 作用 |
|---|---|---|
| `WINNER_EXEMPT_PCT` | **0.15** | 浮盈 ≥ 该值进入赢家状态（≤0 关闭） |
| `WINNER_TRAIL_MULT` | **1.6** | 移动止盈回撤放宽倍数：15% × 1.6 = **24%** 才走 |
| `WINNER_RETREAT_MA` | **20** | 趋势线由 MA10 放宽到 **MA20**（强势票贴着 MA10 常被震出） |
| `WINNER_MAX_HOLD` | **30** | 最长宽管交易日数，超过后恢复常规监管（防无限持有） |

⚠️ 设计为"放宽"而非"豁免"，因为归因同时显示**持有 10 日均值 −3.85%**
——完全不管会让赢家最终回吐。赢家仍有退出纪律，只是容忍更大的自然震荡。

### P1-1 阈值比例重置（★盈亏比自洽★）

这是 V4.8 复盘就提出的硬规则：**止损上限必须 ≤ 止盈上限的一半**。V4.8 是
"赚 10% 就减半、亏 12% 才砍"，可达盈亏比上限仅 0.83，面板实测 **0.56**（保本需 2.50）。

| 参数 | V4.8 | **V4.9** | 说明 |
|---|---|---|---|
| `ATR_STOP_MAX_PCT` | 0.12 | **0.06** | 亏损端才是决定项（3 笔止损吃掉 −4.1 pp） |
| `ATR_STOP_MIN_PCT` | 0.05 | **0.04** | 留出 [4%, 6%] 的自适应窗口 |
| `PARTIAL_TAKE_PCT` | 0.10 | **0.15** | 不再在赢仓刚起步时砍半 |
| `TRAIL_PCT` | 0.10 | **0.15** | 与 6% 止损配对 |
| `STOP_STAGED` | True | **False** | 删除两段式（V4.8 实证 3/3 同一分钟内走完两段） |
| `USE_OWN_COST`（新增） | — | **True** | 判据改用策略自有成本 `g.entry_px` |

**可达盈亏比上限 = 15% / 6% = 2.50**（V4.8 为 0.83），首次具备保本可能。

**自有成本**：V4.8 发现平台 `cost_price` 在部分卖出后被摊薄（两段式的"第二段÷第一段"
浮亏比值 = 1.69 / 1.79 / 1.78，三个独立样本高度一致），所有基于百分比的阈值都会漂移。
V4.9 改在建仓时锁定 `g.entry_px[code]`，**分批减仓后保持不变**，正是判据所需的性质；
`cost_price` 只用于对账。

### P1-2 出场原因统一追加浮盈亏

V4.8 的 31 笔出场里 **19 笔**（破均线 14 + 移动止盈 5）的 reason 不含浮盈亏，
复盘时无法评估出场质量。现由 `_do_sell` **内部自动计算并追加**（单点封装，杜绝遗漏）；
已含"浮"字样的 reason 自动跳过，不会重复。

## 二、离线校验结果（25 项 0 失败）

| 场景 | 断言 | 结果 |
|---|---|---|
| EXP-1 自有成本 | 注入污染成本 11.5、自有成本 10.0：按 10.0 算 −5% 不触发；关掉后按 11.5 算 −17.4% 被错误止损（**反向对照证明此坑真实存在**） | 3/3 |
| EXP-2 赢家·移动止盈 | 回撤 20% 时赢家不卖 / 30% 时卖出且标注"(赢家宽管)" / 关闭赢家后 20% 即卖出（反向对照） | 4/4 |
| EXP-3 赢家·趋势线 | 已破 MA10 但未破 MA20 → 不清仓；关闭赢家 → 正常清仓（反向对照） | 2/2 |
| EXP-4 浮盈亏追加 | 缺失时自动补"浮盈 20.0%"；已含"浮"字样不重复 | 3/3 |
| EXP-5 主线约束 | 按主线分别计数 / 窗口外旧记录剔除 / 空流水返回 0 | 3/3 |
| EXP-6 参数落地 | 8 个参数值 + **★盈亏比自洽★（6% ≤ 15%×0.5）** + 全局状态初始化 | 10/10 |

**场景构造踩到的坑（已记入技能库）**：浮盈 60% 时 `PARTIAL_TAKE_PCT` 会先命中并 `continue`，
必须先 `g.partial_done.add(code)` 才能隔离出移动止盈分支 —— 与 V4.8 校验器里的
"分支隔离两件事"是同一种坑的新实例。另：`g.pos_hist` 的 row 必须是 **6 元组**
（`_atr` 按 `_, c, h, l, _, _` 解包），少一个字段会直接抛 `ValueError`。

校验器验证的是**行为正确性，不是收益表现**。

## 四、回测观察要点

跑 2026-05-06 ~ 06-30 时请重点看这几项（顺序即优先级）：

1. **盈亏比是否离开 0.56** —— 这是本版的核心目标。保本需 2.50，
   若仍在 1.0 以下说明阈值比例还没配对，或止损仍被别的出口接管。
2. **出场原因分布** —— 现在每笔都带浮盈亏，直接按 reason 分组即可：
   看止损笔数是否下降、单笔均亏是否降到 −6% 附近、盈利端均值是否上升。
3. **平均持仓天数** —— V4.8 是 6.50 天。赢家宽管生效后应上升；
   若反而下降，说明 `WINNER_EXEMPT_PCT=0.15` 偏高、很少进入赢家状态。
4. **`[风控] ... 进入赢家宽管`** 日志条数 —— 直接反映有多少笔获益于本机制（0 条即未生效）。
5. **主线集中度** —— 看 `稀缺资源` 是否仍被反复选中 8 笔以上（若仍是，说明阈值 4 太松）。
6. **`[口径-来源]`** —— 仍是 `assumed(+1.0%)` 属正常（引擎不暴露日内价），不必再排查。

**达标线**：区间收益 > 0%、盈亏比 ≥ 1.5、最大回撤 ≤ 9%、折年双边换手 ≤ 25 次。

## 五、已知局限

1. `WINNER_TRAIL_MULT=1.6` / `WINNER_RETREAT_MA=20` 是**结构性建议值**，未经回测标定；
   若回测显示赢家回吐过多（盈利端均值下降但持仓天数上升），优先调低 `WINNER_TRAIL_MULT`。
2. `MAINLINE_MAX_ENTRIES=4` 同理，是"防止过度集中"的保守起点，可能压低仓位利用率。
3. 主线分散的**端到端跳过行为**本次只做了函数级校验，需在回测中确认没有误伤。
4. 归因样本仅 26 笔、单一区间（2026-05~06），换一段行情需重跑 `工具-选股归因.py` 复核。
