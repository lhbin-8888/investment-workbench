## 三、为什么"几乎什么都没发生"——三重闸门叠加

### 闸门 1：信号模式无成交（设计预期，非缺陷）
`TRADE_ENABLED=False` → `order_target_value` 不调用 → 持仓恒空。由此连锁：
- `_daily_risk_scan` 遍历空持仓 → **止盈/超买/移动止盈全部无对象**；
- `_intraday_hard_stop` 同上 → 日内硬止损无对象；
- `_t_once` 找不到持仓 → **L3 日内T 全期空转**；
- 总资产 = 现金 → 恒定 100,000 → **回撤恒 0 → 断路器永不触发**。

**这是本次回测最大的解释项：信号模式只能验证"信号产生"与"接口可用"，无法验证任何盈亏与风控链路。**

### 闸门 2：换手预算误拦 L1 建仓（★回归缺陷，已修）
2026-01-05 08:30 同一秒打出 **15 条** `[换手预算] 年化 250.0 回合 > 上限 7.5，暂停新开 L2/L3`。
- 第 1 只（茅台）买入成功 → `ytd_turns` +1；
- `_turnover_ok()` 按 `turns × 250 / days = 1 × 250 / 1 = 250` 判定 → 立即超限；
- 其后每只 L1 标的都在 `_do_buy_value` 里被拦下 → **L1 应建 16 只、实际只建 1 只**，58% 底仓只完成 5.3%。

这个拦截是上一轮"让断路器独立拦截"改动的副作用：原写法 `if not _turnover_ok() and g.get("circuit_halt")` 是"与"关系，换手预算不会单独生效；拆开后 `_turnover_ok()` 变成了独立强闸，把 L1 一起拦了——而 `_turnover_ok` 自身文案明写"暂停新开 **L2/L3**"。

### 闸门 3：市场开关 42.5% 交易日处于"下方"

### D8 补充说明：为何首跑没暴露它，以及它到底影响什么

- **为何没暴露**：首跑是信号模式，零成交、无持仓；而 `[pos]` 告警只在 `get_positions()` **抛异常**时打印，**形态错误（返回 dict 却被当 list 遍历）不抛异常**，所以完全静默。**信号模式回测在结构上无法发现此类缺陷。**
- **实际影响（实盘会是致命的）**：`_daily_risk_scan` 遍历空持仓 → 止盈/超买/移动止盈**永不触发**；`_intraday_hard_stop` 同上 → 日内硬止损**永不触发**；`_t_once` 找不到持仓 → **L3 日内T 全程空转**；`_apply_sector_cap` 聚合行业市值恒为 0 → **行业上限 30% 永不生效**；`_l1_rebalance` 见 `cur_val=0` → 季度再平衡按目标市值重复补仓，单票上限判断失真。
- **教训**：凡"返回 dict 还是 list"这类**结构型口径**，必须从官方文档逐字确认，不能靠"跑一遍没报错"推断；且**冒烟测试（零成交）天然无法覆盖持仓/风控链路**。

修正后的口径自洽性：
- 一轮完整 L2 往返（买→卖）= **1 回合**，恰好等于 `COST_PER_TURN`（买+卖综合成本）；
- L1 建仓/再平衡 = **0 回合**（不占投机预算）；
- 一轮 L3 日内T（先卖后回补）= **1 回合**；
- 年化预算判定在第 20 个交易日后才生效，避免早期样本外推。
