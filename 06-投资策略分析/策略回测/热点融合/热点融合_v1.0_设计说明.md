# 热点融合 v1.0 设计说明

> 融合对象：热点早盘001 V4.11 / 热点追踪lhb888 v3 / 热点追踪早盘1030 v8.1
> 目标：取三家之长、避三家之短 —— 更高收益 + 各市场环境下更平滑
> 代码：`热点融合_v1.0_ptrade.py`（PTrade / Python 3.5 兼容）

## 一、融合映射（每一项改动都对应一个"来源优势 + 规避的缺陷"）

| 模块 | 融合做法 | 取自 | 规避的缺陷 |
|---|---|---|---|
| 热点判定 | 申万行业均值排名(前10) ∩ 板块强度分(001:涨停率/上涨率/MA20比/均值) ∩ 共振≥2只(常开) | lhb888行业级 + 001强度分 + 1030共振(改默认OFF) | 1030 无主线筛选的粗口径；001 易空仓 |
| 选股 | 涨幅主板[3.5%,6%]/科创[6%,9%] + 量比≥1.5 + 站MA20&MA60 + 形态≥2 + 日内回撤≤4% + 回踩cur≥open | 折中001窄带 + lhb888严格趋势 + 1030回踩 | 001[4,5]过窄致长期空仓；纯宽松致杂波 |
| 买入 | 10:30 + 每日新≤2 + 冷静期2日 + 双护栏 + 强度加权 + 额度回收3轮 | 1030时点/回收 + 001双护栏/克制 + 放宽频度 | 001每日≤1笔踏空连涨；1030无护栏接刀 |
| 止损 | ATR自适应 clamp[5%,11%]（下限09:45） | 001 ATR思想，但放宽区间 | 001[4,6]被热点波动震出（实测"自适应"退化为5%固定）；1030固定-5%震荡磨损 |
| 止盈 | +10%减半 + 保本+3% + 移动止盈武装5%/回撤15% + 赢家粘性锁利8pp + +30%全清 | 1030分批 + lhb888保本 + 001移动/赢家 | 单一固定止盈截断利润 |
| 破线 | 破10日线(14:45确认,仅浮亏砍) + 破20日线(14:45确认,硬清) | 001破10 + lhb888破20 | 1030破3日线过度交易；lhb888破20过迟 |
| 大市 | 沪深300<MA20暂停新建 + 中证1000<MA20 halt全停 + 情绪冰点HALF减半 | lhb888宽基 + 001小盘halt + 1030情绪闸 | 001/1030单一指数错配；无复合避险 |
| 赢家 | 浮盈≥15%粘性记入 + 自峰值回撤≥8pp清仓（百分点尺，跨日保持） | 001 V4.10赢家宽管 | 001 V4.9"当日浮盈"判定致保护失效（死代码） |
| 换手 | 年≤25次 / 月≤20笔 双向记账 | 001熔断(修双向+交易日窗口) | 1030/旧版换手统计只记买→熔断永不触发 |
| 成本 | 自有 `g.entry_px` 记账，卖出前先快照 | 规避PTrade摊薄成本陷阱(§二十一) | 读 order 后持仓→成本=0→￥全零 |

## 二、为什么"更平滑 + 更高收益"

1. **下行由复合避险兜住**：下跌市里 中证1000 halt（最果断）+ 沪深300 暂停新建 双层，配合破20日线硬清与硬止损下限，回撤被压到最小（对齐001的防御性）。
2. **上行不踏空**：每日新≤2（放宽001的1）、冷静期仅2日、双护栏只挡"接刀/追高"不挡正常建仓，避免001式长期空仓。
3. **利润不被截断**：移动止盈(15%回撤)+赢家锁利(8pp)让主升浪吃到尾；保本+3%把震荡市的赢单变平单概率压低。
4. **震荡市降费**：HALF减半 + 换手熔断 + 额度回收，减少无效进出（对齐1030情绪闸 + 001成本控制）。
5. **选股质量双确认**：行业级(申万均值) + 个股级(强度分) + 共振，避免单看个股的假热点。

## 三、上线前必须自核的接口（逐项确认，别猜）

- [ ] `get_history(count, "1d", [字段], [代码])` 批量返回形态（dict{code:DataFrame} 还是 MultiIndex）——本策略按 dict 取 `panel.get(code)`，若平台为 MultiIndex 需改 `_to_panel` 解析。
- [ ] 持仓形态：`get_positions()` 返回 `dict[str:Position]` 还是 `list[dict]`——已用 `_get_positions` 双形态兼容。
- [ ] 当日价来源：回测 `handle_data` 的 `data` 是否可用；不可用会自动退化快照/昨收（打 `[口径]` 日志核对覆盖率）。
- [ ] `order_target_value(code, value, limit_price=)` 限价参数名（下划线）。
- [ ] 指数代码 `000300.SS` / `000852.SS` 用 `_suffix` 转换，不会被改写。
- [ ] 无 `os` / 网络 / f-string / 类型注解（已编译通过 3.5 语法）。

## 四、验证计划（交付后必做，未做不算完成）

1. **信号模式**先跑 3~5 日，grep `[hist]/[acct]/[pos]` 告警应为 0；确认 `[指纹]★FUSION v1.0★` 出现在首屏（防传错版）。
2. **离线行为校验器**（参照 001 系列）：构造上涨/震荡/下跌剧本，对硬止损、保本、分批、移动止盈、赢家锁利、破20日线、板块冷却、换手熔断逐分支断言。
3. **成交模式**回测 5/6~6/30，输出 `[净值]` + 分原因 `[卖出]` 统计（金额加权 + 扫仓比），与三份原策略对照。
4. 用「持有N日相对基准超额」做选股质量归因，确认融合未引入新损耗。

## 五、已知待调参数（上线前用回测标定）

- `ATR_STOP_MIN/MAX`：热点票波动大，[5%,11%] 为初值，需按真实 ATR 分布核对是否仍被截断（§十 坑1）。
- `GAIN_RANGE` 下限 3.5%：若实测仍频繁空仓，下移到 3.0%。
- `MAX_NEW_PER_DAY=2`：若换手超限，先降到 1 而非动止损。
- `WINNER_GIVEBACK_PCT=8pp`：对 +50% 以上大赢仓可能偏紧（§二十 规则E），可改为 `max(8pp, 峰值×40%)`。

## 六、离线行为校验结果（fusion_validator.py）

采用「Mock 平台接口 + 剧本驱动」方式，对策略逐分支做确定性断言，**24/24 全部通过**。分层覆盖：

| 层 | 覆盖点 | 结果 |
|---|---|---|
| L1 退出分支 | 硬止损(含09:45时间闸门)、保本止损、分批止盈、移动止盈、赢家锁利、止盈全清、破20日线(尾盘确认)、时间止损、板块冷却、换手熔断、ATR自适应clamp[5%,11%] | 13/13 |
| L2 大市检测 | 上升市→NORMAL、下跌市(中证1000<MA20)→HALT、沪深300弱→PAUSE、情绪涨停≥25→OK、涨停<25→ICE | 5/5 |
| L3 买入闸门 | NORMAL建仓、HALT不建仓、PAUSE不建仓、HALF预算减半 | 4/4 |
| L4 端到端 | 3日bull剧本建仓+巡检不崩 | 1/1 |

**校验器在交付前抓出 2 个真实 bug（已修复）：**
1. **致命：`_record_trade` 未定义** —— `_sell_all` / `_sell_half` 调用了不存在的 `_record_trade()`，任何一次卖出都会 `NameError` 直接崩策略。已补 `_record_trade`（记录每笔卖出原因+浮盈率，供分原因统计）。
2. **死代码：`保本止损` 条件矛盾** —— 原 `pnl >= BREAKEVEN_GUARD(3%) and cur <= entry` 中，当前浮盈≥3% 要求 `cur≥103` 而 `cur≤entry=100` 永远不成立，保本保护永不触发（即设计说明点名的"001 V4.9 同类缺陷"）。已改为 `peak_pnl >= BREAKEVEN_GUARD and cur <= entry`（用峰值盈利判定，回撤至成本即退）。

> 校验器本身是一份可复用资产：后续任何 PTrade 策略改版，重跑 `python fusion_validator.py` 即可回归。Mock 关键约定——`get_history` 单只代码返回 Mat（非 dict）、情绪/面板数据时间升序（rows[-1]=今日）。
