## 二、为什么"更平滑 + 更高收益"

1. **下行由复合避险兜住**：下跌市里 中证1000 halt（最果断）+ 沪深300 暂停新建 双层，配合破20日线硬清与硬止损下限，回撤被压到最小（对齐001的防御性）。
2. **上行不踏空**：每日新≤2（放宽001的1）、冷静期仅2日、双护栏只挡"接刀/追高"不挡正常建仓，避免001式长期空仓。
3. **利润不被截断**：移动止盈(15%回撤)+赢家锁利(8pp)让主升浪吃到尾；保本+3%把震荡市的赢单变平单概率压低。
4. **震荡市降费**：HALF减半 + 换手熔断 + 额度回收，减少无效进出（对齐1030情绪闸 + 001成本控制）。
5. **选股质量双确认**：行业级(申万均值) + 个股级(强度分) + 共振，避免单看个股的假热点。

## 七、成交模式回测（fusion_backtest.py）

### 7.1 引擎是什么
事件驱动模拟器，**原文件 `hotspot_fusion_v1_ptrade.py` 一字不改**加载进来，由引擎注入 PTrade API 面：
`get_history / get_Ashares / get_all_stocks / get_industry / get_snapshot / order_target_value / order_target / order / log / context(portfolio+blotter)`。
日内 7 个时点推进：`09:45 / 10:30 / 11:20 / 13:10 / 14:15 / 14:45 / 14:55`；10:30 及之前用当日 `open` 作填充价（双护栏才有意义），其后用 `close`。
成本模型：滑点 买 +0.1% / 卖 -0.1%，佣金 万3（最低5元），卖出印花税 千1。

### 7.2 本轮回测额外抓出 4 个真实 bug（均已修复）
| # | 严重度 | 问题 | 后果 | 修复 |
|---|---|---|---|---|
| 3 | 致命 | `MAX_HIST_BARS` 未定义（`scan_market` 用它作取数根数） | 面板取数抛 `NameError`，被 try/except 吞掉 → **永远 0 候选、永不建仓** | 新增常量 `MAX_HIST_BARS = 60` |
| 4 | 致命 | `held` 被缓存：`g["hold_days"].get(code6, 计算值)` 把建仓日的 0 固化 | `held < 1` 恒成立 → T+1 判断**永远跳过所有卖出分支，只买不卖** | 改为每次用 `first_buy` 重算 |
| 5 | 高 | `_update_regime` 把 `.values`（`[[v],[v],…]`）当一维序列 `sum()` | `int + list` 异常 → **大市避险层（HALT/PAUSE）全线失效** | 新增 `_flatten()`，`_ma()` 与 `series()` 统一展平 |
| 6 | 中 | 分配额买不满 1 手时仍下单（如 6561 元买 195 元/股 = 33 股） | PTrade 静默废单、**预算被白白占用** | 新增最小 1 手闸门 `alloc >= cur*lot*1.02`（科创 lot=200） |

> 说明：bug 3/4/5 在离线校验器里**都没暴露**——校验器只覆盖了分支逻辑与 mock 数据形态，没覆盖"真实取数返回值形状"与"跨日状态演进"。这正是必须做成交模式回测的原因。

## 九、真实回测首跑复盘与 v1.1 修正（2026-09-22）

### 9.1 现象
v1.0 上传 PTrade 跑 2026-05-06 ~ 06-30，结果是 **全天 0 成交**：每天 08:30 与 10:30 各报一次取数失败，候选池恒为空，净值一条直线。

```
WARNING - [senti] function get_history: invalid field ['pre_close'], valid fields are
          {'open','volume','is_open','money','high','price','preclose',
           'high_limit','low','unlimited','close','low_limit'}, got ['close','pre_close']
WARNING - [扫描] 面板取数失败: function get_history: invalid field ['pre_close'] ...
```

### 9.2 两个根因（都不是语法错，而是**平台契约**错）

| # | 根因 | 后果 | 修正 |
|---|---|---|---|
| A | 字段名写成 `pre_close`；平台只认 **`preclose`**（无下划线） | 面板与情绪取数每次抛异常，被上层 `try/except` 吞掉 → **候选池恒空、全天 0 成交** | 新增字段白名单 `PLATFORM_FIELDS` + `FIELD_ALIAS` + `_norm_fields()`，所有取数一律经白名单过滤 |
| B | **平台日线不含当日 bar**，末根日线是【昨收】；v1.0 把 `closes[-1]` 当今日价、`prec[-1]` 当昨收 | 即使字段名修好，涨幅也会算成"昨日涨幅"、买入价与形态判定全部错一天 | 当日价改从 `data` 快照取（`_cur_bar`），昨收 = `closes[-1]`；取不到当日价就**跳过该票**，绝不用昨收冒充 |

根因 B 的证据来自既有的 1030 策略源码注释（第 917 / 1176 行）：「日线不含当日 bar，最后一根 = 昨收；当日价走 data 参数」。

### 9.3 v1.1 全部修正清单
1. 字段名白名单 + 别名翻译（`pre_close`→`preclose`、`amount`→`money` 等），未识别字段一律剔除，**永不触发 invalid field**。
2. 取数解析改为**按列名对齐**（`_sub_rows` 返回 `{字段名: 列下标}`），不再依赖列顺序——字段被平台剔除或顺序变化时不会静默错列。
3. 当日价四层来源：`data` 快照 → 批量 `get_snapshot` → 分钟线最后一根 → 仍失败则跳过并计数。
4. 量比优先用「当日累计量 / 前5日均量」，当日量不可得时退化为「昨日量比」并计数。
5. 日内回撤、回踩判定改用当日最高/当日开盘（当日值不可得则该道过滤跳过，不误杀）。
6. 情绪口径改为 `昨收/前日收 - 1`（即昨日涨跌幅），与 1030/001 同源，且**不再需要 `preclose` 字段**。
7. 新增 `[扫描] 池N 有效N | 无当日价N 分钟线兜底N 量比退化N` **取数体检行**：以后任何一次跑，看这一行就能立刻判断取数是否正常。
8. 版本指纹升级 `★FUSION v1.1★`，避免线上跑错版本。

### 9.4 为什么上一轮离线校验 24/24 全绿却漏掉了这两个根因
因为**Mock 比平台宽松**，属于典型的"测试夹具失真"：

| 失真点 | 旧 Mock | 已改为 |
|---|---|---|
| 字段名 | 任何字段名都接受并返回 0.0 | 非法字段名**抛与平台一致的异常** |
| 日线口径 | `b.date <= day`（**含当日**） | `b.date < day`（**不含当日**，与平台一致） |
| 单只返回 | 单只恒返回 DataFrame | 单只也返回 `dict{代码: DataFrame}`（平台行为） |
| DataFrame | 只有 `.values` | 同时有 `.columns`（策略按列名取数才跑得到） |

并新增 **L0 平台契约层**测试：① 静态扫描策略源码里所有 `get_history` 字段字面量是否都在白名单内（**覆盖全代码路径，不只跑到的分支**）；② 运行时断言非法字段名会被拒绝；③ 断言无当日价时安全跳过不崩。

## 十七、第十轮：行业表内嵌（v1.7）实现说明

### 17.1 动机

外挂 `sector_map.json` 的三个成本：① 每次上传多带 416KB 文件；② 只读目录路径不确定；
③ 路径不对时整层静默失效（v1.4 踩过）。内嵌后三并解除，代价是策略文件变大。

### 17.2 数据格式

```
"银行:000001 002142 600036|房地产:000002 000006 ...|..."
```

- 板块名与代码用 `:` 分隔，代码间空格，板块间 `|`；
- 代码统一 6 位纯数字（去掉 `.SZ`/`.SS` 后缀），与 `_pure()` 同口径；
- 板块名若含 `:` `|` 等分隔符会被清理并**打印告警**（不静默）；
- 策略侧用相邻字符串字面量按 ~92 字符折行（PTrade 编辑器对超长行不友好），
  语义等价于单串。

### 17.3 幂等标记块

```python
# === EMB_IND_BEGIN ===
# source: ... / generated_at: ... / 原表 416.2KB -> 内嵌 95.7KB
EMB_SECTOR_RAW = (
    "..."
)
# === EMB_IND_END ===
```

生成器每次**整体替换**标记块内容，只重写目标常量，另一常量原样保留 → 可反复执行。
首次执行时插到锚点 `MINUTE_BARS_TODAY = 61` 之前。

### 17.4 加载优先级

```
_load_sector_index()
  ├─ g["ind_rev"] 已缓存            -> 直接返回
  ├─ ① 内嵌 EMB_SECTOR_RAW 非空     -> 解析并 return（零 IO），ind_src="内嵌"
  └─ ② 内嵌为空                     -> 回落外挂 6 路径，ind_src="外挂"
                                     -> 全失败 log.error + 列出已试路径
```

`initialize()` 末尾主动调用一次，使 `[行业]` 行出现在启动阶段（不再被懒加载淹在后面）。
日志带 `来源=内嵌/外挂` 与覆盖数，作为 runbook 判据。

### 17.5 验收

- 内嵌表与源表 **逐条零差异**（496 板块 / 5582 只，`ast` 提取 + 复刻解析比对）
- 离线校验器 **88/88**（含 `L1.内嵌表覆盖标的达标`、`L1.行业表加载走内嵌优先`）
- 本地引擎链路 OK
- 因只改加载方式，**真机行为预期与 v1.6.1 一致**（变量隔离）

### 17.6 注意事项

- **写盘必须 `newline="\n"`**：Windows 文本模式默认把 `
` 写成 `

  会让 2719 行文件整体变 CRLF、体积虚增 2.7KB、与仓库其他文件不一致。
- **体积天花板未知**：策略 191.7 KB（原 89.4）。若 PTrade 上传被拒，退 `--gen sw`（125 KB）。
- **内嵌 ≠ 免更新**：数据仍需从源生成，只是变成一条命令 + 单文件上传。
