## 三、新根因：把「昨收」当成了「当日价」

### 3.1 决定性证据（1030 策略同平台的真实回测日志）

`热点追踪早盘1030/热点追踪早盘10：30回测.txt` 第 10、15、16 行：

```
[自检] 日线不含当日 bar，但分钟线可得 → 涨幅按「当日实时价/昨收」计算
[口径] 样本 000001.SZ 昨收=11.13 data价=11.34 price字段=11.13 分钟close=11.13
[扫描] 粗筛完成：5200 只，批量请求 18 次（当日价5107只 / 回退昨日93只）
```

这一行同时暴露三件事，每一件都足以让我们的策略 0 成交：

| 事实 | 对 v1.3 的含义 |
|---|---|
| `data价=11.34` **≠** `price字段=11.13` | **data 对象里"数值本身"才是当日价，按 `price` 字段名读到的是昨收** |
| `分钟close=11.13` **==** 昨收 11.13 | **回测里分钟线给的是【昨日】最后一根**，不能当当日价 |
| 1030 拿到当日价 5107/5200 只 | 唯一可行通道是 `data` 对象，且必须走对入口 |

而 v1.3 的 `_cur_bar()` 正是这么写的：

```python
out["price"] = _pick(src, ("price", "last_px", "last_price", "close"))   # ← 拿到昨收
```

`_pick` 是 `getattr(obj, "price")` —— **第一个候选就是那个给昨收的字段名**。
结果：全池 5179 只的 `cur` 都等于 `prev_close` → `pct = (昨收-昨收)/昨收 = 0`
→ 涨幅区间 `[3.5%, 6%]` 一只都进不去 → `[粗筛]` 恒空 → 0 候选 → 0 成交。

**最恶劣的地方：这条路径一行报错都没有。** 没有异常、没有 warning，只有
`[空转告警]` 每 5 天响一次——它是对的，只是它也只能告诉你"没开仓"，说不出为什么。

### 3.2 旁证：`[统计]` 里那句 `板块强度Top=[('', ...)]`

`''`（空字符串行业名）同时说明两件事：① 板块强度榜的聚合对象**只有 1 只票**（count=1），
即 `[粗筛]` 只过了 1 只、其余 5178 只全被涨幅区间杀掉，与本节推断完全吻合；

## 四、v1.4 修复清单（9 项）

### 4.1 取价层（本轮根因）

1. **新增 `_bar_price(obj, prev_close)`：数值优先**
   候选顺序 = `float(obj)`（数值）→ `close/price/last_price/...` 字段 → `values()`；
   并对**每个候选**做「与昨收相等就作废」的过滤。彻底堵住"拿昨收当当日价"。
2. **新增 `_data_price(data, code, prev_close)`：入口照抄 1030**
   `data.get(code)` 数值 → `data[code]` 数值 → `data.current(code, field)` → `data.get_price`。
3. **新增 `_today_price(...)`：四层兜底 + 每层拒绝昨收**
   `data` → 日线 `price` 字段 → 分钟线 → 保守假设定价（昨收×1.010，001 同口径）。
   最后一层**不弃票**（弃票就等于整池为空）。

### 4.2 口径层

4. **date 列别名** `DATE_COL_ALIASES = (date, datetime, time, trade_date, dt)`
   平台真实列名是 **`datetime`**（本轮 `[诊断]` 实测）。旧代码硬查 `"date"` 恒取空
   → `has_today` 恒 False，而日志照样写"日线不含当日bar" —— **假判定，把排查带偏一轮**。
   现在分别计数 `date列命中 N/M`，命中为 0 时直接 `log.error`。
5. **量比口径修正**：只认「日线含当日」时的当日量；否则明确退化到**昨日量比**并计数。
   旧版把分钟线窗口求和当"当日累计量"，而回测分钟线是昨日 → 全池量比被系统性低估到 ~0.25。
6. **成交额改取平台 `money` 字段**（1030 同款做法），取不到再自算 `volume×close`。
   面板字段集由 5 个扩到 7 个（补 `price`/`money`，两者都在平台白名单内）。

### 4.3 观测层（这一轮真正救了排查的就是它）

7. **新增 `[口径]` 样本自证行**（照抄 1030 第 15 行）：
   ```
   [口径] 样本 600001.SS 昨收=11.130 现价=11.342 涨幅=1.88% 成交额=8.37e+08
          量比=1.14 站MA20=True | 当日价来源=data | data通道命中5179/5179
   ```
   这一行把「昨收 / 当日价 / 涨幅 / 来源」一次性印出来。**若"data通道命中"远小于池子
   规模，或"当日价来源"全是假设定价，就是本轮的病，一眼可见。**
8. **新增 `[粗筛]` 漏斗行 + 淘汰样本 + 自动判读**：
   ```
   [粗筛] 池5179 → 涨幅区间淘汰5178 → 成交额淘汰0 → MA20淘汰0 → 过关1
   [粗筛] 淘汰样本: 000001 pct=0.03%(需3.5~6.0%) | ...
   ```
   九成以上死在涨幅区间 → 直接报"当日价口径仍然不对"；死在成交额 → 报"money 单位不对"。
9. **`[统计]` 增打行业未命中数**，并在出现空行业名时直接 error 提示 sector_map 未生效。

### 4.4 顺手修掉的第二个真 bug：行业归属恒为空

`[统计] 板块强度Top=[('', (0.0504, 1, 0))]` —— 行业名是**空字符串**。

原因：v1.3 的 `_industry_of()` 只试 `get_industry()`（本平台无此接口）→ 恒返回 `""`
→ 全池归入同一个空行业 → **「申万行业均值排名 + 同行业共振≥2」整层等于没做**。
这一层失效不会直接导致 0 成交，但会让"热点"判定退化成纯个股涨幅排序——即使价格修好，
也会选出一堆散票，等于没做"热点融合"。

修法：加载外挂 `sector_map.json`（001 同款文件 + 同款候选路径 + 同款"失败必告警"纪律），
建 `{6位代码: 行业名}` 反查表缓存到 `g`，成功打 `[行业] 加载成功 行业数=496 覆盖标的=5582`，
失败打 3 行 `log.error` 并列出全部尝试路径。

## 七、本轮方法论沉淀（已写入技能 `ptrade-strategy-dev` v3.1.0）

1. **`data` 对象的取值语义是本平台第 4 类契约陷阱**：数值=当日价，字段名（`price`/
   `close`）=昨收。前三类是"取不到"，这一类是**"取得到但值错"**——常规体检指标
   （有效票、键数、字段名、行数）对它**全部免疫**，只能靠"与昨收比对"识别。
2. **回测里 `get_history('1m')` 给的是昨日**，不是当日。任何把分钟线当"当日价/当日量"
   的写法在回测里都会静默退化。识别方法：把分钟 close 与日线末根（昨收）比对。
3. **凡"取价"，必须写一条「与昨收相等即作废」的 guard**（1030 源码 1186/1188 行同款）。
   成本一行，能挡掉整个类别的静默失败。
4. **外挂数据文件的缺失会让整层逻辑静默失效**（sector_map → 行业均值/共振）。
   凡是"读文件建索引"的逻辑，失败必须 `log.error` + 列出全部尝试路径，
   并在下游加"结果异常检测"（如"出现空行业名就报错"）。
5. **体检指标要能区分"没取到"与"取到了但值错"**：必须补一条**值语义自证行**
   （打印样本的昨收 / 现价 / 涨幅 / 来源），否则第 4 类故障永远是黑的。

### 8.3 仍存在的四类问题（分"可信度"与"alpha"两层）

**A. 权益曲线计价失真（约 8 天，影响收益/回撤读数）**

即平台在 HALT/PAUSE 日不给持仓定价（`portfolio_value` 退化为 cash）。
源码 `log_net_value` 直接读 `context.portfolio.portfolio_value`（`hotspot_fusion_v1_ptrade.py:569`），
非自算。终点与峰/谷恰落在正常计价日，故 −1.74% 与 −9.5% 可作为**可信上下界**；
中间这些天被低估。修复：让 `log_net_value` 用 `_today_price` 自算持仓市值，不依赖平台值。

**B. `get_snapshot` 不支持（每日 WARNING）**
回测里用分钟线=昨日价做限价与估值，成交价不真实，实战表现会不同。

**C. 量比因子失效（每日 `量比退化518X`）**
当日 bar=0，量比退化到昨日口径（≈1.0），"放量"过滤实际空转；
选股退化为 涨幅区间 [3.5%,6%] + 成交额≥4e8 + 站MA20 + 行业强度。

**D. 行业未命中随月份走高（2→10）**
sector_map 是 2026-09-21 生成的表，用来跑 5–6 月数据，10 只/日不在表内；
"行业均值+共振"层对这些票退化为个股排序。

| 4 | `[行业] 加载成功 行业数=496 覆盖标的=5582` | sector_map 没上只读目录 |
| 5 | `[口径] 样本 … 涨幅=X.XX%`（非 0） | 又回到取价语义坑 |
| 6 | **`[精选] 粗筛N → … → 候选M`** ← 新增 | 候选怎么没的是黑的 |
| 7 | **`[买入] 当日候选为0（精选层为空）`** ← 新增 | 空转日不可解释 |
| 8 | `[净值] … 持仓市值=Y 平台账=Z`（Y>0 且≈真实市值） | 计价口径异常 |
| 9 | HALT/PAUSE 天数应**大幅下降**（v1.5 是 16 天） | 分层没生效 |

**重点看两处变化**：① 冻结天数；② `[精选]` 里**哪道闸淘汰最多**（这将直接指出
第三层「供给不足」该松哪一道）。任一不过，把那行原样发我。

### 11.8 本轮方法论沉淀（已写入技能 `ptrade-strategy-dev` v3.4.0）

1. **静默 return 是漏斗黑洞**：任何提前 return 必须出声，否则「上游有量、下游为 0」不可观测。
2. **「粗筛过关数」≠「候选数」**：漏斗要逐层计数，否则缩量点找不到。
3. **跨策略交叉验证法**：用旁证策略的成交日反推市场状态，可免拉指数数据；但口径可能不同，只作下限。
4. **仓位腿必须按 regime 分层量化**：全周期平均会把「闸门效应」和「填充不足效应」混成一个数。

## 十二、第九轮：行业层口径错配 —— 「精选层清空」的真实机制（2026-09-22 21:1x）

> 起因：彬哥哥问「`sector_map.json` 这个文件要更新吗？」
> 查表时发现，**"要不要更新"是个次要问题，真正的问题是这份表用错了地方**。

### 12.1 回答①：本轮不用更新（但不是因为它没问题）

| 判断 | 依据 |
|---|---|
| 表龄 | `generated_at = 2026-09-21T08:33:40`，距本次重跑 **1 天**，鲜活 |
| **变量隔离** | 本轮重跑唯一目的是「量闸门腿」。**同时换表 → 两个变量一起动 → 无法归因**。所以本轮坚决不换 |
| 跨期风险 | 这份表是「生成时点」的板块成分。拿它跑 5–6 月历史回测 = **用 9 月的成分算 5 月的强度**，属轻微未来函数（对行业归属影响小，对概念成分影响大） |
| 生成脚本自述 | `gen_sector_map_v3.py` 文档原话：**"V3 静态池会滞后热点周期（3~5 天）。本脚本应每日盘前运行一次"** → 跑实盘/新时段前**必须**重生 |

**结论：本轮不更新；将来跑实盘或新时段前，按日重生。**

### 12.2 回答②：真正的问题 —— 行业层有 4 处口径错配

策略第 25 / 309 / 310 行注释都写着「**申万行业均值**」，但 `_load_sector_index` 实际加载的是
**东财 496 个细分板块**。设计意图与实现不一致，且差距不止粒度一项：

| 维度 | 融合现行（东财 `sector_map.json`） | lhb888（申万 `industry_map.json`） | 后果 |
|---|---|---|---|
| 分类体系 | **496 个细分板块**（成分中位 **15 只**，≤10 只的 188 个 / 37.9%） | **31 个一级行业**（成分中位 **122 只**，最小 20 只） | 粒度细 16 倍 |
| 强度样本 | **只遍历候选池** `for code, f in rough`（涨幅已被粗筛卡在 3.5~6%） | **全市场当日涨幅** `_compute_sector_strength(snap)` | 均值被截断、排序噪声化 |
| 小样本门槛 | **无** | `SECTOR_MIN_STOCKS = 5`（行业内样本 ≥5 才参评） | 微板块噪声直接进榜 |
| 失效保护 | 候选清空 → 当日 0 买入 | `SECTOR_STRONG` 为空时**降级不过滤**（不误杀） | 一道闸能冻死整天 |

**第 2 项最隐蔽**：`ind_avg = {k: _mean(v) for k, v in ind_pct.items()}` 里的 `ind_pct`
**只装了粗筛过关的候选**，不是全市场同行。粗筛已把涨幅卡在 3.5~6%，于是所有"行业均值"
全挤在 3.5~6% 的窄带里，**排序接近随机**。

### 12.3 量化证据（蒙特卡洛，纯噪声行情）

先看**粒度**（2000 次模拟，各股收益 iid N(0,2%)，按板块均值取 Top10）：

| 指标 | 东财表 | 申万表 |
|---|---:|---:|
| 强势榜 Top10 平均成分股 | **3.7 只** | **139.6 只** |
| Top10 里 ≤10 只的小板块占比 | **97.6%** | **0%** |
| Top10 覆盖全市场票数占比 | **0.66%** | **26.82%** |

→ 纯噪声下，东财表的"强势行业榜"实际是「**随机抽 3~4 只票取均值**」，
97.6% 由微板块占据。它不是行业强度，是噪声。

再看**端到端**（3000 次模拟，103 只粗筛过关候选 → 精选层幸存数）：

| | 融合现行（东财） | lhb888（申万） |
|---|---:|---:|
| 精选层幸存（均值） | **1.77 只** | **25.36 只** |
| 中位 | 2.0 只 | 25.0 只 |
| P10 / P90 | 0.0 / 4.0 | 16.0 / 36.0 |
| **直接清空（剩 0）的概率** | **42.9%** | **0%** |
| 命中率 | **1.72%** | **24.62%** |
| 倍数 | — | **14.3x** |

### 12.4 机理：一道**逻辑死锁**

模拟的中间量把机制暴露得很清楚：

- 103 只候选**散落在 77.8 个细分板块**里（平均每板块 1.3 只）；
- 强势榜取"均值 Top10" → 因为**小样本均值的方差大**，这 10 个板块
  **恰恰偏向「只含 1 只候选」的板块**（那只票涨幅高，就把整个板块均值拉上去）；
- 而下一道闸「共振」要求 `ind_cnt[ind] >= MIN_SECTOR_ALIGN(2)`；
- → **榜单选出来的板块，天然过不了共振**。
- 实测：Top10 里满足"候选数 ≥2"的板块平均只有 **0.84 个**，**42.9% 的概率为 0**。

> 这不是"两道闸都太严"，而是**两道闸互相排斥**。所以哪怕把 `TOP_INDUSTRY_N`
> 从 10 调到 50，也只是缓解；根子在"496 细分板块 + 只用候选池算均值"。

**这正好解释 11.2 里那 4 天「NORMAL 却 0 买入」**（05-21 / 06-16 / 06-22 / 06-25，
粗筛过关 98~121 只）。当时只能看到"候选没了"，现在知道**是怎么没的**。

### 12.5 附带缺陷：行业归属不可复现

- 东财表里 **5582 只票有 4788 只（85.8%）属于 ≥2 个行业板块**，最多同时属 3 个
  （属 1 个的仅 794 只、属 2 个 2115 只、属 3 个 2673 只）；
- 而 `_load_sector_index` 的规则是 `if k and k not in rev: rev[k] = name`
  —— **首次出现优先**，其顺序 = JSON 字典序（即板块代码顺序）；
- → 同一只票的"行业"由**文件里的板块排列顺序**决定，**重新生成表就可能变**。
  行业层因此**不可复现**，也无法与历史回测对齐。

### 12.6 修复方案（两条路）

**方案 A（推荐）—— 行业层切到申万一级，与 lhb888 完全同口径**

1. 用 `热点追踪lhb888\industry_map.json`（申万一级，5218 只 / 31 行业）作为行业表；
2. `_load_sector_index` 增加**反查格式支持**（`{code: 行业名}`），两种 schema 都能吃；
3. 补齐 lhb888 的 3 个加固：① 行业均值改**全市场样本**；② 加 `SECTOR_MIN_STOCKS=5`；
   ③ `SECTOR_STRONG` 为空时**降级不过滤**；
4. 收益：行业层从"1.72% 命中率 + 43% 清空"变成"24.6% 命中率 + 不清空"，
   且**与 lhb888 同口径**，两边收益才真正可比。

**方案 B（最小改动，保留东财表）**

1. 行业均值改全市场样本（不再只用候选池）；
2. 只保留成分数 ≥30 的板块参评（≥30 只的板块共 140 个，Top10 覆盖从 0.66% → 8.60%）；
3. `TOP_INDUSTRY_N` 由 10 → 50（覆盖 7.11%）；
4. 加归属去重规则（按板块成分数降序或固定白名单），保证可复现。

**补充**：东财表并非无用 —— 它的 `concept` 部分（504 个概念板块）正是
"概念热点共振"的好素材。原始设计注释写的是「**申万行业均值 + 001 板块强度分**」
双通道，现在两个功能挤在一张粒度错的表上，才是问题的本质。

### 12.7 对下一轮重跑的影响

## 十三、第十轮：行业表内嵌（v1.7）—— 把 416KB 外挂文件塞进策略

### 13.1 结论：能，而且推荐 —— 但先分清「省什么」

| 想省的 | 内嵌能否省掉 |
|---|---|
| 每次上传要带第二个文件 | ✅ 省掉，变成**单文件上传** |
| 只读目录路径赌不对 | ✅ 省掉，**零 IO、零路径依赖** |
| 漏传导致整层静默失效 | ✅ 省掉（v1.4 踩过的坑） |
| **数据源的更新工作量** | ❌ **省不掉** |

**关键澄清：内嵌不是「免除更新」，而是「把更新从手工搬运变成一条命令」。**
表仍由 `gen_embedded_map.py` 从源表生成，只是不再需要手动上传。

另外要分清「什么才是日频变化的」：
- **行业/概念归属**（本表）：申万一级几乎不变，东财细分板块也是月度级 → **不需要每天更新**；
- **行情**（涨幅/量比/资金流）：这才是日频数据，但它来自平台接口，不来自本表。
- 生成脚本注释里写「应每日盘前运行一次」是针对**实盘静态池**的时效设计，不是归属本身在变。

### 13.2 体积测算（先算再做）

JSON 把板块名重复存了 N 遍（`"000505": "农林牧渔"` × 5218 条）。
**反向组织**成 `"板块名:代码 代码 ...|板块名:..."` 后板块名只存一次：

| 内容 | 原始 | 压缩后 |
|---|---:|---:|
| 东财 industry（496 板块 / 13043 人次） | 416.2 KB | **95.7 KB** |
| 东财 concept（504 板块 / 32382 人次） | — | 227 KB |
| 申万一级（31 行业 / 5218 只） | 123.6 KB | **36.0 KB** |

策略文件：**89.4 KB → 191.7 KB**（+99.3 KB，2719 行）。
⚠️ PTrade 单文件大小上限未实测；若上传被拒，可退到 `--gen sw`（125 KB）。

### 13.3 实现（三层解耦）

1. **生成器** `gen_embedded_map.py`：读源表 → 压缩 → **幂等替换**策略文件里的成对标记块
   （`# === EMB_IND_BEGIN ===` / `# === EMB_IND_END ===`）。支持三种源：
   东财 industry / 东财 concept / 扁平 `{code:行业名}`（如申万）。
2. **策略侧** `_parse_emb_sector()`：解析压缩串 → `{code6: 板块名}`，结果缓存到 `g`
   （避免 5582 只逐票重复解析）。
3. **加载策略** `_load_sector_index()` 改为 **内嵌优先、外挂兜底**：
   内嵌非空即用（零 IO）；为空才回落原有 6 路径逻辑。**双保险**。

### 13.4 独立性验证（关键）

不能只信「能跑」，必须证明**内嵌表 ≡ 源表**。做法：用 `ast` 从策略文件提取 `EMB_SECTOR_RAW`
字面量 → 复刻策略解析逻辑 → 与源表 `{板块: [代码]}` 反向索引**逐条比对**：

```
内嵌解析 -> 板块 496 / 覆盖标的 5582
源表解析 -> 板块 496 / 覆盖标的 5582
逐条比对：板块数一致、归属零差异、无多余条目  ALL PASS
```

校验器从 76/76 掉到 73/76，其中一项是运行时用例

## 十五、第十二轮：v1.7 真机实测 —— 收益率为什么更差了（−10.46%）—— 2026-09-22 22:1x

> 上一轮（第十四章）把 [精选] 漏斗的预测钉死，然后跑了 v1.7。漏斗形态全对，
> **但收益率反而从 −1.74% 掉到 −10.46%**。这一章解释为什么，并给出 v1.8。

### 15.1 一句话结论

**「松闸」放大了负期望。行业层口径不是 P&L 的主因 —— 它只决定「做几笔」；
决定「赚不赚」的是入场/退出结构本身。**

v1.5 的 −1.74% 不是因为闸门对，而是因为 v1.5 的大市闸门**锁死了 16 个交易日**，
让一个**负期望**的入场逻辑少交易了。v1.7 把 8 天从 HALT 松成 HALF（可建仓），
于是多做了 9 笔**单笔期望 −504 元**的交易。

| 归因项 | 金额 | 占总亏损 |
|---|---:|---:|
| HALF 档买入的 9 笔 | **−4,536** | 46% |
| NORMAL 档买入的 21 笔 | **−5,386** | 54% |
| 合计（台账口径） | **−9,923** | 100% |

→ **两档都是负的。**所以"松闸"只是把问题放大，不是问题的来源。

### 15.2 真机账面（先对账，别急着解释）

| 项 | 数值 |
|---|---|
| 区间 | 2026-05-06 ~ 06-30，**39 个交易日** |
| 起点 / 终点 | 100,000 → **89,540** = **−10.46%** |
| 峰值 | 105,175（05-14，+5.18%） |
| 峰终回撤 | **−14.87%** |
| 买入 / 卖出 | **31 笔 / 32 笔**，期末空仓 |
| 净值曲线形状 | 5 月上半月冲高 → **05-14 见顶** → 之后单边阴跌 → 06-08~06-15 连续 6 天全空仓 → 尾部续跌 |
| 对照 | v1.5 = −1.74%；**v1.7 比 v1.5 差 8.72 个百分点** |

⚠️ 一个容易被忽略的事实：**策略在 05-14 是 +5.18% 的**。全部亏损发生在 05-14 之后。
这说明**不是"这套逻辑从来不赚"，而是"5 月下半月起这套逻辑系统性失效"**。

### 15.3 成交台账重建（本轮真正的取证）

日志里每笔卖出都带平台自己报的 `浮盈x%`，配合委托行的 `数量：买入N股` 与 `限价`，
就能重建一张完整台账。工具已固化为 **`trade_ledger.py`**（本目录，可复用）：

```
python trade_ledger.py [日志路径]      # 默认读 热点融合回测1.txt
```

> ⚠️ **三个必守口径（我踩过第一个）：**
> ① 股数取委托行里的**真实股数** `数量：买入N股`，**不能**用 `分配 ÷ 限价` 估 ——
>    那是策略的**名义**下单量。我第一次用名义量估，把 700 股算成 771 股，单笔亏损被放大 10%。
> ② 部分平仓（减半 / 赢家锁利）要按持仓批次 **FIFO 扣减**，不能当全平。
> ③ 台账结果必须与日志 `[净值]` 期末值**对账**（本轮 −9.92% vs −10.46%，差 **0.54pp OK**）。

| 退出原因 | 笔数 | 合计盈亏 | 均值浮盈 |
|---|---:|---:|---:|
| **硬止损** | **16** | **−14,444** | **−7.58%** |
| 保本止损 | 9 | −653 | −0.51% |
| 时间止损 | 2 | −242 | −1.30% |
| 赢家锁利 | 4 | +3,925 | +8.18% |
| 减半 | 1 | +1,491 | +13.80% |
| **合计** | **32** | **−9,923** | — |

**三行读出来的东西：**

1. **唯一失血口是那 16 笔硬止损：−14,444，占全部毛亏（15,205）的 95%。**
2. **保本止损这一层是好的**：9 笔均值只有 −0.51%。它不该被"优化掉"。
3. **止盈那 5 笔均值 +9.30%，质量不差 —— 只是太少**（5 : 27）。

### 15.4 三个决定性指标 + 打平需要什么

| 指标 | v1.7 实测 | 含义 |
|---|---:|---|
| 单笔胜率 | **5/32 = 15.6%** | 每 6.4 笔才 1 笔赚钱 |
| 盈亏比（毛额口径） | **0.356** | 毛盈 5,416 / 毛亏 15,205 |
| 赔率（单笔均值口径） | **1.60** | 平均盈 +9.30% / 平均亏 −5.80% |
| 单笔期望 | **−310 元 / 笔** | 每开一笔平均烧 310 元 |
| 退出结构 | 止损类 **27 笔(84%)** vs 止盈类 **5 笔(16%)** | **5.4 : 1** |

**自洽检查**（这个式子必须能对上，对不上说明口径错了）：

```
期望 ≈ 15.6%×(+9.30%) + 68.8%×(−5.80%) + 15.6%×0 = −2.53% / 笔
```

**要在现结构下打平，三条路任选其一（都不涉及"调闸门"）：**

| # | 需要 | 现值 | 目标 | 难度 |
|---|---|---|---|---|
| ① | 胜率 | 15.6% | **38.4%** | 需要把 22 笔亏损单砍掉 10 笔 |
| ② | 平均盈利 | +9.30% | **+31.3%** | 放大 3.4 倍（不现实） |
| ③ | 平均亏损 | −5.80% | **−1.72%** | 止损收紧 3.4 倍（等于一买就砍） |

**三条路都很陡。②③ 显然不成立，所以唯一现实的方向是 ①——提高胜率，也就是"别买在会被埋的位置"。**

### 15.6 按买入档位再切一刀：HALF 比 NORMAL 更危险

| 买入日大市档 | 已平仓 | 合计盈亏 | 单笔均值 |

  而**这个群体在 05~06 窗口的 5 日收益本身就是 −3.56%**。
  策略精选层选出来的票，收益与「同档位随机票」**逐档重合**（差 −0.03pp / −0.06pp）——
  **精选层（行业榜/共振/形态/回踩/强度分排序）既没加分也没减分，病灶根本不在那里。**

**一句话：不是筛得不好，是"什么时候筛"错了 —— 10:30 筛出来的就是当天要回落的票。**

### 16.5 取证方法：剥离出场规则，只看入场

**动机**：只看净值永远分不清这两种病因 ——
(A) 出场太紧，好票被砍在半路（→ 优化出场有意义）；
(B) 入场本身没 alpha（→ 出场只是放大器，怎么调都没用）。
两者处理方式**完全相反**。

**做法**：把每笔买入当成一个独立赌注，**完全忽略策略的止损/止盈**，
只用真实日线算 T+N 收盘收益，再穷举出场规则看天花板在哪。

**口径（两处踩坑，已写进工具文件头）：**

1. **成本价 = 日志 `[买入]` 行的"限价" ÷ 1.02。**
   源码 L2023 `limit = min(cur*1.02, hi_guard)`，而 `entry_px = cur` ——
   即**日志里的"限价"是委托价，不是成交价**。
   实测验证：41 笔的 `限价÷1.02` **全部落在当日真实价格区间内**；
   而直接用限价则有 **22/41 笔"高于当日最高价"**（见 16.9 的自我纠错）。
2. **行情用腾讯不复权日线**（`param=...,day,start,end,320,` 尾参留空）。用前复权会在除权票上引入偏差。

**产出**：`entry_alpha_check.py`（新增工具，见 16.12）。

### 16.6 证据一：裸持有收益（入场信号的真实表现）

41 笔买入，入场价 = 当日 10:30 价（= 限价 ÷ 1.02），持有到 T+N 收盘，**完全无视策略的止损止盈**：

| 持有期 | 均值 | 中位 | 胜率 | 最差 | 最好 |
|---|---:|---:|---:|---:|---:|
| T+1 收盘 | −0.22% | −0.43% | 46.3% | −7.7% | +18.8% |
| T+2 收盘 | −0.00% | −0.52% | 46.3% | −13.2% | +17.8% |
| T+3 收盘 | −0.81% | −0.58% | 39.0% | −18.9% | +23.2% |
| **T+5 收盘** | **−3.17%** | −2.35% | **34.1%** | −26.8% | +18.6% |
| **T+10 收盘** | **−5.43%** | −5.29% | 34.1% | −33.9% | +25.2% |

**两条硬结论：**

**注意一行容易看漏的数据**：策略实际出场 **−1.95%**，**好于**裸持有 T+5 的 −3.17%。
⇒ **出场规则实际上是在减亏的（+1.22pp），它不是罪魁。** 这一点修正了上一轮"出场是病灶"的初步判断。

**另一个反直觉的数**：5 日内最大浮盈（MFE）均值 **+6.54%**、中位 +4.13%、**胜率 92.7%**。
即 92.7% 的票买入后都出现过正浮盈，平均最高摸到 +6.54%。但 T+5 收盘均值 −3.17% —— **这份浮盈被系统性回吐**。

### 16.9 ⚠️ 一个必须交代的自我纠错（本轮中途差点误报）

排查中我一度得出"**41 笔里 22 笔的买入价高于当日最高价 → 买入价虚构 → 回测数字全是假的**"，
并准备把它作为本轮头号结论。**这是错的。**

查源码后发现：

```python
# L2019-2023
lo_guard = cur * (1 - BUY_FLOOR_PCT)     # 0.985
hi_guard = cur * (1 + BUY_PREMIUM_PCT)   # 1.03
limit = min(cur * 1.02, hi_guard)        # → 实际就是 cur * 1.02
order_target_value(..., limit_price=limit)
g["entry_px"][code] = cur                # ← 策略内部成本价是 cur，不是 limit
```

**日志里的"限价"是委托价（`cur × 1.02`），不是成交价。** 用一个本来就故意高于市价的委托限价
去比对"是否超出当日最高价"，当然会得到荒谬结果。

**这个错误同时暴露了我自己的一个工具 bug**：`trade_ledger.py` 旧版直接把"限价"当成本价，
每笔**成本额被系统性高估 2%**，污染单笔期望与对账。已修正为 `成本价 = 限价 ÷ 1.02`，
修正后台账与净值对账差从 **0.67pp → 0.53pp**。

> **教训：任何"数据看起来荒谬"的结论，下判断前先回读产出这份数据的源码。**
> 口径来自代码，不来自字段名的字面含义 —— 这在 PTrade 平台上已经第 9 次应验。

### 16.10 证据四（本轮决定性）：全市场样本外对照 + 闭环

**（3）因此真正的根因（本轮最终答案）**

> **策略用"10:30 盘中时点涨幅"选股，系统性地选中了「早盘冲高、随后回落」的股票群体
> （41 笔里 54% 收盘已跌回 3% 以下，平均收盘涨幅仅 +2.62%）。
> 而这个群体在 05~06 窗口本身的 5 日收益就是 −3.56%。
> 精选层做得再精细，也只是在这个负收益群体里挑 —— 收益与随机挑同档票无异。**

**这一条同时解释了此前所有"修了却没转正"的现象：**

| 现象 | 用本结论解释 |
|---|---|
| 第九轮：改行业层口径（v1.7→v1.8）只减亏不转正 | 病灶不在行业层，改口径只是换了批同样负收益的候选 |
| 第十五轮："松闸"后收益更差 | 放进更多同类（冲高回落型）票 |
| 本轮：出场端 22 条规则天花板为零 | 群体的收益分布是负的，任何出场规则都榨不出正期望 |
| 15.3：硬止损是最大失血口 | 冲高回落型票天然容易触发止损 |

**注意一个重要的口径差异（必须写明，避免误读）**：
样本外检验用的是**当日收盘涨幅**（可执行：尾盘下单确认），
策略用的是**10:30 盘中时点涨幅** ——
**两者不是同一群体**：10:30 涨 3~4% 的票，收盘可能继续冲到 6%（强势延续），也可能回落到 1%（冲高回落）。
闭环对照显示的正是：**策略系统性地落在了后一类**。

### 16.12 本轮方法论沉淀

**新增 / 修正的工具（放在策略目录，可复用）：**

| 文件 | 用途 |
|---|---|
| **`entry_alpha_check.py`**（新增） | **入场 alpha 检验器**：剥离出场规则，算 T+N 裸持有 / MFE / MAE / 入场区间位置，穷举 22 条候选出场规则给出"出场端天花板"，并自动判定该修入场还是修出场 |
| `trade_ledger.py`（已修） | 台账重建；本轮修正**成本价口径**（限价÷1.02），对账差 0.67pp → 0.53pp |
| `check_funnel_prediction.py`（已修） | `[精选]` 行尾注正则兼容 v1.7/v1.8 |

**用法：**

```
python entry_alpha_check.py [日志] [--json out.json]   # 入场 alpha + 出场天花板
python trade_ledger.py [日志]                          # 单笔期望 / 胜率 / 硬止损占比
python check_funnel_prediction.py [日志]               # P 系列 / Q 系列预登记判据
```

**核心知识点（已写入技能 `ptrade-strategy-dev` §四十八）：**

1. **"减亏"与"转正"是两件事** —— 参数对齐只能减亏；要转正必须改期望来源。
2. **失血口会转移** —— 堵一个洞，钱从另一个洞流出去（v1.8：硬止损 −60%，时间止损 ×6.5）。
   **所以验收必须盯"单笔期望"这一个数，不能盯分项。**
3. **分离入场与出场的唯一方法**：剥离出场规则测裸持有 T+N。
   T+N 单调恶化 = 入场问题；T+N 明显好于实际出场 = 出场在毁钱。
4. **穷举出场规则给出"天花板"** —— 若最优规则仍 <0，则调参这条路在数学上已封闭。
5. **"精选层是否有效"必须用同档位对照来验，不能只看自己的收益** ——
   把策略的票按某个可复现的维度（如当日收盘涨幅）归档，与全市场同档比较；
   **差距≈0 就说明筛选层没创造价值**（本轮 −0.03pp / −0.06pp）。
6. **盘中时点涨幅（如 10:30）不是一个可用的选股信号** ——
   它度量的是"早盘冲高"，不是"强势"。**度量时点选错，后面全白做。**
7. **预登记判据少用 `AND` 复合条件** —— 容易留下"字面通过"的口子；
   **优先选与阈值无关的硬证据**（如"天花板为负"）作为裁决。
