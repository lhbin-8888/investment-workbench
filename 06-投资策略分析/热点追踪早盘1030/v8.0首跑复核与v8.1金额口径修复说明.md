## 三、根因：先下单、后读成本

| | v8.0（有 bug） | `_sell_half`（正常） |
|---|---|---|
| 顺序 | `enable = 读可卖量` → **`order_target(code, 0)`** → `_cost = 读成本价` → 算 ￥ | **`_cost = 读成本价`** → `order(code, -qty)` |
| 结果 | 下单返回后持仓已被清空，`cost_price = 0` → ￥ = 股数 × 0 × 浮盈 = **0** | 先读后下单 → ￥ 正确 |

PTrade 回测中 `order` / `order_target` 返回时**即已完成撮合并更新持仓对象**，
之后再读 `cost_price` 一律得到 0。这是典型「副作用先于读取」的顺序错误。

## 四、v8.1 修复

**修复内容**：把成本价与 ￥盈亏 的计算整体**上移到下单之前**（`_sell_all` 与 `_sell_half` 统一写法）。

**影响面**：只动统计与日志，**不触碰任何交易逻辑**。已用 `difflib` 逐块核对：
v8.0 → v8.1 共 **14 处差异**，全部落在 docstring / 注释 / 预设表 / `_sell_all` 记账顺序 /
`_sell_half` 注释 / 初始化日志；`order_target(code, 0)` 的调用条件与位置**一字未动**。

**回归测试**（`verify_v81.py`，31 项断言全通过）用 mock **复现引擎真实副作用**（下单后持仓清零）做双向对照：

| 被测版本 | mock 语义 | 输出 |
|---|---|---|
| v8.0 | 下单后清零（真机） | `[卖出] 600000.SS 数量1000 ￥+0` ← **bug 复现** |
| v8.1 | 下单后清零（真机） | `[卖出] 600000.SS 数量1000 ￥+2,200` ← **修复** |
| v8.0 | 空函数（旧测试） | `￥+2,200` ← 旧测试为何"假绿" |

⚠️ **教训**：v8.0 当天是通过验证才上线的，但 `verify_v8.py` 把 `order_target` 写成了空函数，
**没有复现"下单即清零持仓"这个副作用**，于是测试"假绿"。已写入技能。

## 五、顺带查到：v3 基线的口径需要确认

复核 v3 日志（`热点追踪早盘10：30回测.txt`）时发现两处需要你确认的事：

**1. 策略名不同**

```
v3 日志头部：开始运行回测, 策略名称: lhb热点追踪早盘10：30
R6 日志头部：开始运行回测, 策略名称: 热点追踪10：30优化
```

前者是 `lhb`（龙虎榜）版，后者是 `优化` 版。需确认这是**同一策略的两个命名**，还是**两条不同的策略线**。

**2. 自算收益 ≠ 标称收益**

| | 数值 | 来源 |
|---|---|---|
| 标称 v3 收益 | **+6.67%** | 回测界面（我们一直引用的数） |
| 该日志自算期末 | 06-30 快照 **103,174 元 → +3.17%** | 日志 35 条 `[买入] 总资产` 快照 |
| 日志峰值 | 06-23 **111,118 元（+11.12%）** | 同上 |

胜率是对的（清仓 63 笔中赢 23 笔 = 36.5%，与标称 35.94% 吻合），**但收益差 3.5pct**。
可能原因：① 这份日志不是产出 +6.67% 的那一次；② 界面口径含收盘市值，而 `[买入] 总资产`
是 **10:30 时刻**的快照，两者不可直接比。

**⇒ 建议核对：+6.67% 是哪一次回测、哪个日期范围、什么口径。**
在确认之前，跨版本对比请一律用**同口径的日志快照**（我们上一轮的净值曲线就是这么做的，结论不受影响）。

**同口径对照（都是 10:30 快照，可比）**：

| | v3 | R6 | 差 |
|---|---|---|---|
| 06-30 快照 | 103,174 | 101,176 | **-1,998 元（约 -2.0pct）** |
| 界面收益 | (+6.67%) | +3.23% | (-3.44pct) |

两个口径给出的差距不同（2.0pct vs 3.44pct），因为 06-30 两版仓位结构不同、尾盘涨幅不同。
